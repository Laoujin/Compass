Always-on box, replaced.

Four angles — CPU, vendor versus DIY, storage layout, and power/acoustics — converge on a single box that runs containers and ML workloads without a custom-OS lock-in.

Where the four angles agree 3 layers

Hardware sets the ceiling, storage decides recoverability, and acoustics gate where the box can actually live.

layer 1 · hardware

CPU + vendor-vs-DIY

Sets the ceiling. The DIY path wins on flexibility and longevity but adds an OS-maintenance tax the vendor boxes hide. If you'd rather spend evenings on Scout than apt upgrades, vendor NAS + TrueNAS is the path of least surprise.

verdict · vendor box, third-party OS
layer 2 · data

Storage layout

Decides the recoverability story. ZFS mirror beat btrfs raid1 and mdraid+ext4 unambiguously on recovery. Two 16 TB drives, mirror not raidz, restic to B2 carries offsite.

verdict · ZFS mirror + restic
layer 3 · room

Power & acoustics

Gates whether the box can live where you work. Any 2-bay tower with 3.5″ spinners falls into the "office only" category — full stop. Power draw is a side-show next to acoustics in a shared room.

verdict · office, not living room

What broke the tie 3 wedges, ranked

Three things, in order of weight — the load-bearing reasons one option won and the others didn't.

1
heaviest

AVX2 is now table stakes

The workloads you actually run — llama.cpp, ffmpeg, modern Docker bases — all assume AVX2. The aging Synology CPU lacks it. Anything you buy has to clear that bar before any other criterion matters.

2
decisive

ZFS won on recovery

The storage angle's case for ZFS over btrfs was unambiguous on the recovery story. zpool import survives more failure modes than btrfs raid1's history of trickier rebuilds.

3
disqualifier

Acoustics drew a hard line

The acoustics survey put any 2-bay tower with 3.5″ spinners in the "office only" category — full stop. Idle wattage is a budget question; dBA at 1m is a where-it-lives question.
