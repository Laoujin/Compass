Step 01 · Spec

Slack DM as the prompt.

A direct message to @claude-bot. No channel, no audience tax — just a typed feature request and a thread to live in. Slack push delivers to the phone like any other message.

Why DM: threaded approvals, mobile push, no public chatter. The thread becomes the audit log.

Step 02 · Bridge

Cloudflare Worker, then NAS.

Slack hits a Worker that verifies the signature, takes the 3-second ack budget off the bot, and forwards through a Cloudflare Tunnel to the self-hosted runner. No exposed NAS port, no inbound firewall rule.

Why a Worker: TLS terminates at the edge, retries are cheap, and the bot stays unaddressable from the public internet.

Step 03 · Work

Agent SDK plans, then pauses.

Claude Code reads the repo, drafts a plan, and stops at the first destructive step. The Agent SDK's tool-use approval hook is the gate — every Edit, Bash, or migration call sends a Slack prompt before it runs.

Why Agent SDK: the approval hook IS the mobile UX. No custom protocol — just one Slack message per tool call.

Step 04 · Approve

One tap on the phone.

A Slack Block Kit card with the diff, the migration, and three buttons. Go resumes the agent. Edit reopens the thread for a refinement message. Stop kills the session and rolls the workspace back.

The mobile-friendly bit: approval is a thumb tap on a card that already pushed to the lock screen. No SSH, no laptop.

Step 05 · Branch + PR

GitHub App, no checkout.

The same App that authenticated the agent now creates the branch through the contents API, opens the PR, and posts the link back to the Slack thread. Status checks land on the PR; the preview deploy fires as the third check.

Why one App identity: branch creation, PR open, and check writes share the same installation token. No new secrets, one unified actor in audit.
~12s branch → PRno local clone

Step 06 · Deploy

Compose stack per branch.

A templated docker-compose.preview.yml stamps a fresh stack named after the PR number. Caddy's wildcard cert covers any new subdomain — #312.preview.sangu.be works the moment the web container is healthy.

Why Compose, not k3s: the NAS already runs Container Manager. The whole lifecycle is compose up on PR-open and compose down on PR-close (or TTL).

Step 07 · Review

Same phone, real preview.

The Slack thread that started the request now contains a clickable URL that opens a real, isolated preview of the change — same database shape, same routing, same cert. Tap the button, see the modal, decide.

Closing the loop: spec, build, branch, PR, deploy, review — all in one Slack thread, all from one device. Merge from the same phone, or push to a laptop later.

Two questions the children couldn't fully resolve.

  • Stack garbage collection. PR-close webhooks vs TTL. The auth survey leans TTL — webhooks miss when bots can't observe PR events reliably across forks and stale tokens.
